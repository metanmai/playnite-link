# Playnite Link 0.5.9: link once

One per-game menu item replaces the five technical actions: Link game for unlinked games, Cloud sync for linked games. The link picker has one Link game action, an existing-cloud-game selector or new game name, and an optional local save-folder picker. Save folder selection is part of linking; paths are validated, overlap is rejected, running games cannot change save roots, and existing save roots cannot be silently moved. No save folder is guessed. Linking queues background synchronization under the device's existing pause/automatic-sync preferences.

The linked-game page shows the cloud name, automatic progress status and local save folder. History and options is collapsed; troubleshooting is nested within it. Raw ledger records, identity strings, baseline figures, migration language and repair actions are removed from the primary view and game context menu. Existing settings and history are retained. The legacy save-settings entry point routes to the same game page.

Actual isolated Desktop A and Fullscreen B tested adding a game on A, choosing it by name on B, selecting local save folders during linking, automatic first sync without pressing Sync now, save-file delivery from A to B, actual eight-second game sessions on each client, six repeated syncs per phase, reopening A and checking convergence. One game, one mapping, two sessions and 16 seconds remained consistent with GameActivity. Both GameActivity and HowLongToBeat were enabled; this change does not claim a new online HLTB submission test. UI checks asserted one context-menu action, no raw ledger list in the game page, and collapsed history options. Screenshots of the rendered WPF views were reviewed. Failed cloud lookup and publication retry keep their duplicate-prevention tests.

Regression assertions: 58 ledger/game-picker, 63 vault/connection and 18 activity passed. See friendly-059-automatic evidence for the local Rclone two-client run. The same final flow passed against the authorized personal Google Drive connection in a unique acceptance-test subfolder: A, B and reopened-A all passed. Evidence: friendly-059-cloud-{A,B,Verify}.json. Both new links performed their first sync automatically without a separate Sync now action. The save file matched on both devices and six repeated syncs per phase left one game, two sessions and 16 seconds.
