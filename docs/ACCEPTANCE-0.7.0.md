# Playnite Link 0.7.0 acceptance

Tested 23 October 2026 on Windows 11, Playnite 10 / SDK 6.18 and .NET Framework 4.8. This release integrates the original MIT Playnite Achievements 4.1.1 component rather than reimplementing its provider/UI features. The component's manifest is renamed so Playnite registers only Link. Source and release hashes are recorded in vendor/PlayniteAchievements/UPSTREAM.md.

| Desktop host | 82 checks passed in a real isolated Playnite process: built-in component with no separately registered achievement add-on, original overview/settings rendering, Link sidebar navigation/live status, backup core/session/receipt integration, custom states, fresh and existing catalog projection, icon hash verification and corruption recovery. |

Immutable earned-history merge retains genuine unlock observations and the earliest known date, handles stale/duplicate delivery and compatible progress, and separates conflicting denominators. Deliberate manual changes use a separate causal customization graph, so an old provider observation cannot erase the user's explicit relock. Simultaneous divergent customization edits are retained for review. Provider account identifiers are hashed locally into scope where supported; credentials and complete account/config databases never sync. Unknown/ambiguous identifiers fail closed.

Catalog transfer seeds a fresh engine cache and adds missing rows to an existing compatible provider/account cache. Existing rows retain their provider metadata; normal provider refresh updates it. Blob icons are SHA-256 verified, written to temporary files and atomically replaced; damaged existing icons are reverified. Save/session transfer continues when optional achievement work is deferred, and overall status requests review rather than claiming complete success.

Full original tools are available locally, including friends, capture, notifications, themes and appearance settings. Cross-device payloads comprise current-user game data and portable per-game customizations. Friend caches, screenshot/video capture media, service credentials and machine-specific appearance/capture/notification settings are not cloud-replicated. This is not a claim that every original preference or media file is shared.

Physical ROG Ally controls, real service sign-in/refresh for every supported provider and actual gameplay unlocking on both physical devices remain unobserved here. The current Ally diagnostic prompt checks the installed 0.7.0 component, dashboard and cross-device evidence without replacing saves or copying credentials. Earlier enrollment/WAN and abrupt-termination gates were closed in AUDIT-CLOSURE-2026-10-22.md; they are distinct from these new hardware/provider limits.

Reproduce with tests/Run-Regression.ps1, tests/Run-HostProbe.ps1 -SaveManagerProbe -Mode Desktop (and Fullscreen), tests/Run-AchievementPeers.ps1 and AchievementCloudProbe.exe. Cloud tests require this device's own authorization and an isolated validation destination. Test profiles and private logs stay outside the repository; published evidence contains fixture summaries only.
