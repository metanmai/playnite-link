# 0.6.1 — installed-profile and Bloodborne validation

Date: 23 October 2026. This report supplements the complete upstream feature
inventory in ACCEPTANCE-0.6.0.md. It supersedes that report's installation status.

## Receipt upload fix

Testing the user's existing large library exposed excessive receipt upload work:
0.6.0 sent the entire accumulated outbox, including games without save paths.
The fixed-size upload timeout could expire before the current receipts committed.

0.6.1 reports configured save games and a necessary transition to disabled. It
uploads only receipts generated by the current operation and confirms precisely
that successfully uploaded set. Old unuploaded outbox files cannot become local
confirmation receipts. Immutable old cloud history remains intact.

Two additional regression cases cover a 250-game library with two configured
save games, the one-time disabled transition, and selective confirmation excluding
abandoned outbox records. The full regression gate passed 301 cases, including
44 Save Manager replacement cases, setup termination recovery and nine retirement
safety cases. Actual Desktop and Fullscreen replacement probes passed 47 assertions
each against this build. Sanitized evidence is in `evidence/save-manager-061`.

## Migration and installation

The user explicitly waived the unavailable legacy archive. Nine distinct available
Dispatch archives were copied, imported and verified, then checked again after a
fresh application restart. Original configuration, metadata and available orphan
archives were preserved. Migration did not restore or change live Dispatch saves.

The old extension was moved outside Playnite's Extensions folder. Its original
data is retained as a private recovery copy. Link uses its own provider authorization
file and a verified copy of Rclone in its own runtime folder. This PC's previously
removed device status was explicitly reactivated to permit the requested sync.

## Real Bloodborne save validation

The installed bbport launcher configuration and its actual runtime log identified
the save source as `{GameDir}\user\savedata\1\CUSA00207`. This includes the
`SPRJ0005` save directory and accompanying `SPRJ0005.sce_sys` metadata, while
excluding shader caches, game content, mods and unrelated user directories.

The set contains 15 files totaling 15,002,530 bytes before the game test. A separate
recovery copy was SHA-256 verified before testing. Actual save bytes were used for
native ZIP creation, isolated byte-for-byte restore, stale-file removal, stale
checkpoint rejection, and native CRC rejection of a deliberately modified ZIP.
The installed extension also restored the live folder to the identical original
bytes and retained a pre-restore archive.

Isolated copies of these same saves passed concurrent offline branches,
cancellation without changing bytes/checkpoints, explicit choice convergence and
retention of all four revisions. These deliberately modified conflict fixtures
were never launched or copied to the live save folder.

Fresh remote hashing and the separate client's initially uncached cloud restore
passed. The actual game-start callback and restore rejection during the running
game also passed. The PC game process then terminated with a runtime null-write
fault during this test. The test companion also encountered an exclusively open
runtime log; neither event is counted as a successful character load or clean
exit. Character loading/gameplay and physical Ally transfer remain unverified.
The original verified recovery copy and pre-restore backups remain available.
User-specific final restart checks are recorded in the private installation
report. No second physical PC was used by the PC acceptance test.

Existing unrelated playtime edits in the normal library remain reviewable rather
than being overwritten to force a global “up to date” state. Per-game confirmed
save receipts and fresh remote hash checks are the acceptance criteria for the
Bloodborne save test.
